# Next.js + Tailwind v4 + ESLint + Prettier + next-themes + shadcn/ui
## Complete, Error-Free Setup Guide

This is the final, working sequence — every fix from trial-and-error baked in. Follow top to bottom on a fresh project and you won't hit any of the errors we debugged.

---

## 0. Prerequisite
```
node -v
```
Node 18.18+ required (Next 15).

---




## 1. Scaffold the project
```
npx create-next-app@latest my-app
```
Choose:
- TypeScript: **Yes**
- ESLint: **Yes**
- Tailwind CSS: **Yes**
- App Router: **Yes**
- Import alias: **Yes** → `@/*`

```
cd my-app
```

Confirm `tsconfig.json` has:
```json
"paths": { "@/*": ["./*"] }
```

---





## 2. Install all packages (grouped — avoids dependency-tree churn)

```
npm i next-themes --legacy-peer-deps
```

```
npm i -D @tailwindcss/typography --legacy-peer-deps
```

```
npm i -D eslint-config-standard @eslint/eslintrc @eslint/js eslint-plugin-n eslint-plugin-promise eslint-plugin-import --legacy-peer-deps
```

```
npm i -D prettier eslint-config-prettier eslint-plugin-prettier prettier-plugin-tailwindcss --legacy-peer-deps
```

> **Note:** We deliberately do NOT install `eslint-plugin-tailwindcss`. It only supports Tailwind v3's JS config format and breaks (`Unexpected top-level property "name"` / `is not iterable`) against Tailwind v4's CSS-based config. `prettier-plugin-tailwindcss` sorts classes instead, with zero ESLint conflicts.

## 5. `context/Theme.tsx`
```tsx
'use client'

import { ThemeProvider as NextThemesProvider } from 'next-themes'
import type { ComponentProps } from 'react'

export function ThemeProvider({
  children,
  ...props
}: ComponentProps<typeof NextThemesProvider>) {
  return <NextThemesProvider {...props}>{children}</NextThemesProvider>
}
```

**Why this shape:** it's a wrapper component (not a re-export), giving you a hook point for future logic. `ComponentProps<typeof NextThemesProvider>` avoids depending on `next-themes`' internal (unstable) type paths.

**Save with LF line endings** — CRLF (`␍`) on this file caused Prettier errors earlier. Set in `.vscode/settings.json` (below) to prevent recurrence.

## 6. `app/layout.tsx`
```tsx


import localFont from 'next/font/local'

import { ThemeProvider } from '@/context/Theme'

import './globals.css'

import type { Metadata } from 'next'

const inter = localFont({
  src: './fonts/InterVF.ttf',
  variable: '--font-inter',
})

const spaceGrotesk = localFont({
  src: './fonts/SpaceGrotesk-VF.ttf',
  variable: '--font-space-grotesk',
})

export const metadata: Metadata = {
  title: 'Devflow',
  description:
    'A community-driven platform for asking and answering programming questions. Get help, share knowledge, and collaborate with developers from around the world. Explore topics in web development, mobile app development, algorithms, data structures, and more.',
}

export default function RootLayout({
  children,
}: Readonly<{ children: React.ReactNode }>) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body
        className={`${inter.variable} ${spaceGrotesk.variable}`}
        suppressHydrationWarning
      >
        <ThemeProvider
          attribute="class"
          defaultTheme="system"
          enableSystem
          disableTransitionOnChange
        >
          {children}
        </ThemeProvider>
      </body>
    </html>
  )
}



```

**Key fixes baked in:**
- Import order matches ESLint's `import/order` rule: external → internal → sibling (`./globals.css`) → type. Wrong order was the #1 recurring lint error.
- `suppressHydrationWarning` on **both** `<html>` AND `<body>` — theme scripts modify `<html>`'s class, and browser extensions (ColorZilla's `cz-shortcut-listen`, etc.) inject attributes onto `<body>`. Missing either one caused hydration warnings.
- No `Geist`/`Geist_Mono` default fonts — those trigger a `camelcase` ESLint error and aren't part of this project's font setup anyway.

## 7. `components/ThemeToggle.tsx`
```tsx

// components/ThemeToggle.tsx
'use client'

import { useTheme } from 'next-themes'
import { useEffect, useState } from 'react'

export default function ThemeToggle() {
  const { theme, setTheme } = useTheme()
  const [mounted, setMounted] = useState(false)

  useEffect(() => {
    setMounted(true)
  }, [])

  if (!mounted) return null

  return (
    <button
      onClick={() => setTheme(theme === 'dark' ? 'light' : 'dark')}
      className="btn-secondary text-dark100_light900 body-semibold rounded-md px-4 py-2"
    >
      {theme === 'dark' ? 'Light Mode' : 'Dark Mode'}
    </button>
  )
}


```
The `eslint-disable` comment suppresses a legitimate false positive: the "wait until mounted" pattern is the officially recommended way to avoid hydration mismatches with `next-themes`, but Next's newer React Compiler lint rules flag it anyway.

- **`failed to patch window.location setter`** — caused by an unrelated browser extension (`chrome-extension://caiblelclndcckfafdaggpephhgfpoip`) trying to override `window.location`. Not related to your app; page still loads with `200`. Disable the extension in `chrome://extensions` if the console noise bothers you, or ignore entirely.
